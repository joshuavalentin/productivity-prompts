# Prioritization

## Purpose

Define a consistent prioritization model for combined productivity overviews.

## Priority order

Evaluate work using this order:

1. **Hard commitments** — appointments, explicit deadlines, promised deliverables, urgent client obligations.
2. **Blocking work** — actions that unblock another person, project, or dependent task.
3. **High-value active work** — work already in progress that should be finished before starting new work.
4. **Important near-term work** — meaningful tasks due soon or required for upcoming meetings.
5. **Maintenance/admin** — necessary but lower-leverage operational work.
6. **Backlog/ideas** — optional work without an immediate commitment.

## Decision factors

Consider:

- due date and time;
- lateness or overdue state;
- external dependency;
- whether someone is waiting;
- calendar constraints;
- estimated effort when known;
- context switching cost;
- active-project limits;
- consequence of delay;
- explicit user priority.

## Rules

1. User-stated priority overrides inferred priority unless it conflicts with a hard external commitment the user may have overlooked; in that case, surface the conflict.
2. Do not treat every overdue task as automatically urgent.
3. Prefer finishing active work over starting another optional project.
4. Protect calendar commitments and preparation time for important meetings.
5. Keep the recommended active focus small: normally one primary focus and no more than three must-do items for a day unless the data clearly requires more.
6. Distinguish `waiting` items from work the user can execute now.
7. Do not schedule more work than the visible day can realistically contain.
8. If priority cannot be determined because key data is missing, say so rather than inventing certainty.
